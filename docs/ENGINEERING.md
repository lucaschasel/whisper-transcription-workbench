# 个人工作台设计

## 本机工作区

单人使用，无账号页面、登录接口或会话 Cookie。服务只监听回环地址，写请求继续校验来源和自定义请求头。旧文件与任务在事务中迁移到内部 local 标识，保留已有记录。数据库旧表暂留用于兼容，应用不再提供工单或账号功能。

## 上传与识别

React 页面将选择文件、预听、语言设置和提交放在同一区域，结果直接显示在右侧，历史默认折叠。空文件、格式和大小错误即时显示。上传进度使用真实 XHR 事件；上传失败可重试；文件已上传而创建任务失败时复用资源与幂等键，避免重复创建任务。

FFmpeg 按音频内容解码为 16 kHz 单声道浮点采样，再交给 Whisper，兼容无扩展名存储和 VBR MP3。时长按实际采样数量计算，最多解码 30 分钟加 1 秒，以确认是否超限。损坏媒体、超时和超长有明确错误码。

模型目录从 `WHISPER_MODEL` 推导，接口只公开目录中实际存在的 `.pt` 文件名和大小。创建任务时校验模型 id，并将选择写入任务记录；Worker 再按白名单解析路径，避免客户端传入任意本机路径。模型选择属于任务，排队与重试不会受后来默认模型变化影响。

HTTP 服务不等待模型推理。SQLite 为状态来源，前端轮询更新。调度器串行领取任务，每次执行使用独立 token 与输出目录，提交前核对 token，旧执行不能覆盖新尝试。取消先记为 CANCEL_REQUESTED，子进程终止后才记为 CANCELLED。重启时未完成执行标记失败，用户可手动重试。

当前使用单机锁和串行 GPU 推理，不提供多机调度。每次识别重新加载模型，简化隔离和取消，代价是加载耗时。一次短样本的处理时间不能代表长录音性能。

## 前端边界

基于 React 与 TypeScript，Composer、TaskDetail 各自管理表单和结果。按钮提交锁与服务端幂等共同防止重复操作；文字按纯文本显示。预听使用对象 URL 并及时释放；历史原始媒体接口支持 Range，便于浏览器拖动播放。

可继续扩展：字幕校对稿、点击时间轴定位播放、记录搜索、批量导出。新增功能应保留原始识别结果，明确区分编辑稿。
